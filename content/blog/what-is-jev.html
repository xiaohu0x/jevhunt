Jev is TypeSafe AI's decision model for software. Give it text as state and questions with a defined answer space; receive choices, scores or yes/no probabilities that your application can use.

A decision model has a different job from a chat model

The official introduction describes Jev as a System One model. Its output is a typed judgment, rather than a paragraph, code completion or explanation. That makes it useful at a decision point: which queue receives a ticket, whether a retrieved passage is relevant, or which handler should take a request.

A surrounding application can still generate text. For example, Jev can select the support team while a separate language model writes a draft response. The routing judgment and the generated response have different responsibilities and need separate evaluation.

What does state mean?

State is the material being judged: a message, a document excerpt, a record, or a JSON object containing the relevant facts. It is not automatically a persistent memory store. Your application decides which context to send on each request.

{
  "message": "The upload fails after I choose a PDF.",
  "product": "Document organizer",
  "available_teams": ["technical", "billing", "account"]
}

Questions describe what to decide about that state. Keep the document itself out of the instruction field, name the relevant state fields, and omit unrelated history. All questions in one request see the same state independently; a later decision that depends on an earlier answer needs a subsequent step in code.

Choice, Score and Noul

The three documented question types
TypeUse it forRead from the answer
ChoiceOne option from a defined set, such as a department.Selected option, option probabilities and confidence.
ScoreAn ordered descriptive rubric, such as urgency levels.Score, level probabilities and confidence.
NoulAn independent yes/no statement, such as whether a refund is requested.A probability from 0 to 1 that the answer is yes.

The primitive documentation defines the response fields. A Choice always selects from the supplied options, so include an appropriate fallback when your categories do not cover every input. Use separate Nouls when several tags can apply together.

A structured answer can still be wrong

Constrained output prevents an unexpected answer label; it does not guarantee a correct judgment. Confidence and option probabilities are useful signals, but neither replaces a labeled test set or the application's permission rules. There is no universal threshold that makes every workflow reliable.

For an initial integration, record the input, actual model version, answer and eventual correct outcome. Decide which cases can proceed automatically and which require review. Test how coverage and errors change together when you adjust the threshold.

What should stay outside Jev?

The documented API accepts text, not raw screenshots, sound or video. Other components must turn those inputs into text or structured fields. Jev also does not become a conversational assistant merely because a community app uses its name.

The Jev 1.13 failure notes recommend keeping arithmetic and date comparisons in code and testing adversarial or irrelevant context. Use ordinary parsers for exact extraction, deterministic checks for permissions, and a generative model when the required output is prose.
